# STEM 4CUT

서울STEM축제용 로컬 포토스트립 앱입니다. 운영자가 드론을 비행·조종하고, 참가자는 가로형 태블릿에서 촬영합니다. PC의 FastAPI 서버 한 개가 카메라 캡처, 사진 저장·합성, 인쇄 대기열, 빌드된 React 화면을 제공합니다. 비행 제어 기능은 없습니다. MockCamera와 MockPrinter가 기본이므로 장비가 없어도 처음부터 끝까지 시연할 수 있습니다. 설치를 마친 뒤에는 인터넷 없이 같은 로컬 네트워크에서 사용할 수 있습니다.

## 실행 화면과 순서

| 주소 | 용도 |
| --- | --- |
| `http://localhost:8000/admin` | 운영자 PC: 세션 시작·종료, 장비 설정, 인쇄 대기열, 재인쇄, 복구 |
| `http://<PC-IP>:8000/tablet` | 참가자 태블릿: 시작 → 장수 선택 → 촬영 → 프레임 선택 → 사진 선택 → 출력 |
| `http://<PC-IP>:8000/display` | 외부 디스플레이: 촬영·편집 진행 상태 |

참가자 화면은 **1280×800 Android Expanded 가로형 태블릿**을 기준으로 설계했습니다. 기본 배율에서 주요 단계가 한 화면에 보이고, 터치 버튼과 사진 선택 영역은 최소 48 CSS px입니다. 실제 기기에서는 브라우저를 전체 화면으로 열고 운영 전 터치감과 글자 크기를 확인하세요.

운영자가 **새 세션 시작**을 누르면 태블릿 랜딩 화면의 **시작하기** 버튼이 활성화됩니다. 참가자는 2/4/6개 스트립 중 받을 장수를 먼저 정합니다. 그 뒤 4~6장을 촬영하고 프레임을 선택한 다음, 촬영한 사진 중 서로 다른 네 장을 선택합니다. 선택 순서가 인쇄 순서입니다. 개별 사진의 크롭·위치·확대 조절은 제공하지 않습니다. 합성 시 프레임 슬롯에 맞춘 가운데 크롭만 자동 적용합니다. 화면의 카메라·사진 자리는 비워 두고, 선택 가능한 프레임 이미지만 표시합니다. 촬영 사진은 번호와 선택 순서로 구분합니다. 원본 사진 저장, 합성, 출력은 정상 동작합니다. 같은 세션의 일반 인쇄 요청은 여러 번 눌러도 한 작업만 생성됩니다. 재인쇄는 운영자가 명시적으로 요청해야 합니다. `인쇄 요청이 접수되었습니다`는 실제 종이 배출 성공을 뜻하지 않습니다.

스트립은 **600×1800 px, 300dpi, 2×6인치**이고, 동일한 스트립 두 개를 좌우에 놓은 시트는 **1200×1800 px, 300dpi, 4×6인치**입니다. 2/4/6개 스트립은 각각 1/2/3장의 시트가 됩니다. 원본 JPEG, `strip.png`, `sheet_4x6.png`는 `data/sessions/<세션-ID>/`에, 페이지 수에 맞춘 PDF는 `data/prints/`에 저장됩니다. 프레임 슬롯은 기본 532×319 px(약 5:3)입니다.

## 프레임 추가와 다이얼 선택

태블릿에서 옆 프레임 터치, 좌우 스와이프 또는 키보드 방향키로 다이얼을 돌립니다. 마지막 프레임 다음에 첫 프레임이, 첫 프레임 앞에 마지막 프레임이 이어집니다. 중앙의 큰 프레임을 터치하면 선택됩니다. 현재 기본 프레임은 2종이며, 8~10종을 추가하면 중앙과 양옆 세 칸씩 가로로 표시됩니다.

새 프레임은 `assets/frames/<프레임-ID>/`에 `background.png`, `overlay.png`, `thumbnail.png`, `manifest.json`을 넣습니다. 배경과 오버레이는 600×1800 px이고, 썸네일은 1:3 비율(권장 180×540 px)입니다. `manifest.json`의 이름과 네 개 슬롯 좌표는 기존 프레임을 복사해 수정할 수 있습니다. **PNG 세 파일을 먼저 복사하고 manifest.json을 마지막에 넣으세요.** 준비가 끝난 프레임은 서버 재시작이나 태블릿 새로고침 없이 선택 화면에 약 1초 안에 나타납니다. 복사 중인 불완전한 폴더는 목록에 표시하지 않습니다.

## Windows 10/11 설치 및 한 번에 실행

1. Python 3.11 이상과 Node.js 20.19 이상 또는 22.12 이상을 설치합니다. `py`, `npm` 명령이 PATH에 있어야 합니다.
2. 저장소에서 `scripts\run_windows.bat`를 실행합니다. 첫 실행에는 PowerShell 설치 스크립트가 가상환경, Python 패키지, OpenCV·pywin32 장비 어댑터, 프레임 이미지, npm 패키지와 프런트엔드 빌드를 준비합니다. 이후 실행은 저장된 빌드를 사용합니다.
3. PC 브라우저에서 `http://localhost:8000/admin`을 열고 **새 세션 시작**을 누릅니다.
4. PowerShell에서 `ipconfig`로 PC의 같은 Wi-Fi/LAN IPv4 주소를 찾습니다. 태블릿에서 `http://<PC-IP>:8000/tablet`로 접속합니다. Windows 방화벽에서 Python의 TCP 8000 포트에 대한 **사설 네트워크** 접속을 허용해야 할 수 있습니다.
5. 기본 Mock 모드로 촬영부터 인쇄 요청까지 진행하고, 운영자 화면의 인쇄 대기열과 `data/` 결과 파일을 확인합니다.

수동 설치/재빌드:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\setup_windows.ps1
.venv\Scripts\python.exe -m backend.app.run
```

설정값은 `config.example.yaml`을 `config.yaml`로 복사해 변경합니다. `host`, `port`, `data_dir`, `admin_pin`, 카메라·시리얼·프린터 초기 모드, 선택적 촬영 지연을 지정할 수 있습니다. `config.yaml`은 로컬 전용입니다. 장비 선택은 `/admin`에서 저장하면 `data/devices.json`에 남아 서버 재시작 후에도 유지됩니다. 모드를 바꾸고 싶으면 관리자 화면을 사용하거나, 서버를 종료하고 `data/devices.json`을 검토한 뒤 `config.yaml`을 변경하세요. 서비스 상태와 로그는 `/admin`에서 확인합니다.

관리자 API는 기본적으로 **PC의 localhost에서만** 허용됩니다. LAN의 다른 기기에서 운영자 화면을 써야 한다면 `config.yaml`에 강한 `admin_pin`을 설정하고 서버를 재시작한 뒤, 해당 브라우저의 관리자 화면에 PIN을 입력합니다. 태블릿 사용자는 PIN이 없어도 참가자 기능을 사용할 수 있습니다. 공용 Wi-Fi에서는 관리자 PIN 사용과 신뢰할 수 있는 로컬 네트워크가 필요합니다.

## 클라우드/Linux 개발 실행

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/generate_frames.py
cd frontend && npm ci && npm run build && cd ..
.venv/bin/python -m backend.app.run
```

`npm` 기본 캐시 디렉터리에 쓸 수 없는 클라우드에서는 `npm_config_cache="$PWD/../.npm-cache" npm ci`를 `frontend`에서 사용하세요. `scripts/run_cloud.sh`도 준비되어 있습니다. 개발 중 프런트엔드만 실시간 갱신하려면 `frontend`에서 `npm run dev`를 실행하며, `/api`와 `/ws`는 8000 포트로 프록시됩니다. 행사 운영에는 Vite가 필요하지 않고 FastAPI가 빌드 결과를 직접 제공합니다.

## 실제 장비 연결

### 카메라

- `/admin`에서 `MockCamera`, `HTTP MJPEG/JPEG`, `USB UVC`를 선택합니다. HTTP 모드는 **MJPEG 프리뷰 URL**과 별도의 **JPEG 스냅샷 URL**을 입력합니다. 스냅샷은 GET 또는 POST를 지정할 수 있습니다. 참가자 브라우저가 카메라 IP에 직접 접속하지 않고 PC가 스트림을 중계합니다. 현재 UI에서는 미리보기 영역을 비워 두지만 카메라 어댑터의 스트림 연결은 유지됩니다. 스냅샷 URL이 없는 카메라는 최근 MJPEG 프레임을 저장하며 인쇄 화질 주의 메시지를 표시합니다. 카메라 스트림과 원본 스냅샷의 해상도를 현장에서 확인하세요.
- USB 모드는 OpenCV와 장치 번호(`0`, `1` 등)를 사용합니다. USB 프레임이 인쇄에 충분한 해상도인지 확인하세요. 연결이 끊기면 서버가 다시 프레임을 시도하고 상태를 표시하며 세션·기존 사진은 유지됩니다.
- 장애 시 관리자 화면에서 Mock 모드로 전환하거나, 진행 중인 촬영 세션에 JPEG/PNG/WebP 사진 파일을 **수동 추가**할 수 있습니다(20MB 이하, 최대 6장). 태블릿 촬영 버튼은 시리얼 장치와 무관하게 작동합니다.

### 물리 셔터

- XIAO ESP32-C3 USB 수신기가 **UTF-8 한 줄 `SHUTTER\n`**을 보내는 제안 규약입니다. 관리자 화면에서 COM 포트와 Baud rate를 선택합니다. `READY`, `PING` 등은 무시합니다. 실제 펌웨어의 메시지 형식이 달라지면 `backend/app/remote/serial_receiver.py`를 맞춰야 합니다.
- 시리얼 셔터와 화면 버튼은 같은 촬영 함수를 호출합니다. 약 650ms 안의 중복 신호와 저장 중 중복 호출은 무시합니다. 촬영 단계 밖에서는 새 사진을 만들지 않습니다. 드론 조종기나 비행 제어 장치와는 별개입니다.

### Windows 프린터

- `/admin`에서 설치된 프린터를 선택하고 `Windows 프린터` 모드로 바꿉니다. **Windows 프린터 기본 인쇄 설정에서 4×6인치 세로 용지와 무테 옵션**을 먼저 맞춰야 합니다. 앱은 기본 용지 크기가 약 4×6인치인지 검사하고, 드라이버 인쇄 가능 영역에 종횡비를 유지하여 배치합니다. 무테 인쇄 시 가장자리 확대/잘림, 색상, 실제 출력 크기는 프린터·드라이버·용지 조합으로 현장 교정이 필요합니다.
- `MockPrinter`는 같은 PNG 및 페이지 수에 맞는 PDF를 저장하고 작업 상태를 **파일 저장**으로 표시합니다. Windows 인쇄 어댑터는 스풀러 전송 후 **스풀 전송됨**으로 표시하며 물리 배출은 확인하지 않습니다. 오류 또는 재시작 전 전송 중단으로 상태가 불명확한 작업은 운영자가 프린터 큐를 확인한 뒤 재시도합니다. 운영자 화면에서 테스트 페이지도 요청할 수 있습니다.

## 저장·복구·개인정보

세션 단계, 촬영 전 선택한 장수, 사진 목록, 선택 프레임, 선택한 네 사진의 순서, 인쇄 작업은 `data/studio.sqlite3`와 로컬 파일에 보관됩니다. 브라우저 새로고침·재접속·서버 재시작 후 활성 세션을 복원합니다. 서버 시작 시 기존 세션의 편집 좌표는 제거하고 사진 선택 순서를 유지합니다. `queued` 작업은 처리하고, 전송 도중 중단된 `sending` 작업은 중복 인쇄를 피하려고 `uncertain`으로 표시해 자동 재전송하지 않습니다. 인쇄 중에도 새 촬영 세션을 시작할 수 있습니다. 세션 종료가 이전 인쇄 작업을 취소하지 않습니다.

이름·연락처·얼굴 분석 정보는 수집하지 않습니다. 행사 후 세션을 모두 종료하고 인쇄 대기열이 비었는지 확인한 다음 `/admin`의 **종료된 사진·출력물 일괄 삭제**를 사용하세요. 이 기능은 원본·결과 PNG·PDF와 세션/인쇄 기록을 삭제합니다. 백업 정책은 PC 운영자가 별도로 정해야 합니다.

## 자동 검증

```bash
.venv/bin/python -m pytest -q
cd frontend && npm run build
# 서버가 실행 중이고 Chromium이 설치된 환경에서:
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

2026-10-12 클라우드 환경에서 Python 3.12.14, Node.js 24.19.0으로 프런트엔드 `tsc -b && vite build` 성공, 백엔드 자동 테스트 **6개 통과**, Chromium 브라우저 Mock 종단간 흐름 통과를 확인했습니다. Android 터치 모드의 1280×800 화면에서도 전체 참가자 흐름을 실행하고, 각 단계의 가로·세로 넘침이 없으며 모든 터치 버튼이 48 CSS px 이상임을 확인했습니다. 9종 프레임 다이얼 회전·스와이프·키보드 조작, 열린 화면의 프레임 목록 갱신, 서버 재시작 없는 새 프레임 추가·선택·합성도 검증했습니다. 자동 테스트는 랜딩→장수 선택→촬영→프레임→사진 선택→출력 순서, Mock 6장 촬영과 서로 다른 이미지, 화면·시리얼 중복 촬영 방지, 사진 가공 입력 거부, 가운데 크롭 합성, 600×1800/1200×1800 및 300dpi, 좌우 시트 픽셀 동일성, 2/4/6개→1/2/3장 PDF, 인쇄 요청 멱등성·명시적 재인쇄, 세션 재시작 복구, HTTP 카메라 오류 후 사진 수동 추가, 프린터 오류 후 다음 팀 촬영·재시도, 관리자 접근 제한을 검증합니다. 실제 Windows PC·태블릿·카메라·시리얼 수신기·프린터의 통합 연결과 종이 출력은 이 Linux 클라우드에서 검증할 수 없으며 행사 전 실물로 확인해야 합니다.
